# План реализации: расширение «Складской учет номенклатуры»

## Исходные данные

- База: `D:\YandexDisk\1C Programming\DataBases\db001` (файловая), платформа 8.3.27, режим совместимости 8.3.18.
- Основная конфигурация практически пустая (`Документ1`, `РегистрСведений1`), справочника номенклатуры нет.
  Поэтому все нужные объекты (номенклатура, склады, регистры) создаются в самом расширении.
- Расширение: имя `СкладскойУчет`, назначение «Дополнение», префикс `ск_`.
- Исходники хранятся в формате выгрузки Конфигуратора (`src/cfe`), загрузка — скриптом `tools/load-extension.ps1`.

## Модель данных

| Объект | Назначение |
|---|---|
| Справочник `ск_Номенклатура` | Товары: артикул, единица измерения, штрихкод EAN-13 (генерируется автоматически, если не задан) |
| Справочник `ск_Склады` | Места хранения |
| Регистр накопления `ск_ТоварыНаСкладах` (остатки) | Физический остаток: Номенклатура, Склад → Количество |
| Регистр накопления `ск_ТоварыВРезерве` (остатки) | Резерв: Номенклатура, Склад, ДокументРезерва → Количество |

Свободный остаток = `ск_ТоварыНаСкладах` − `ск_ТоварыВРезерве`.

## Этапы

### 1. Документы (п. 1 ТЗ)

- **`ск_ПриходТоваров`** — склад, ТЧ «Товары» (номенклатура, количество, цена, сумма).
  Движения: приход в `ск_ТоварыНаСкладах`.
- **`ск_РасходТоваров`** — склад, необязательная ссылка на документ резерва, ТЧ «Товары».
  Движения: расход из `ск_ТоварыНаСкладах`; если указан резерв — одновременно снимает резерв
  (в пределах зарезервированного количества).
- **`ск_РезервТоваров`** — склад, ТЧ «Товары». Движения: приход в `ск_ТоварыВРезерве`.

Контроль при проведении (общий модуль `ск_КонтрольОстатков`), с управляемыми блокировками:
- остаток на складе не может стать отрицательным;
- резерв не может превысить физический остаток (свободный остаток ≥ 0) —
  то есть нельзя зарезервировать больше, чем свободно, и нельзя отгрузить чужой резерв.

### 2. Отчет по товарам в резерве (п. 2 ТЗ)

Отчет `ск_ТоварыВРезерве` на СКД: остатки резерва на дату с группировкой Склад → Номенклатура → Документ резерва,
плюс колонки «Остаток на складе» и «Свободный остаток». Отборы по складу и номенклатуре.

### 3. Печать штрихкода на этикетке (п. 3 ТЗ)

- Общий модуль `ск_ШтрихкодыСервер`: расчет контрольной цифры EAN-13, генерация внутреннего штрихкода
  (префикс `2`), построение изображения штрихкода EAN-13 (BMP) средствами встроенного языка —
  без внешних компонент и БСП.
- Общий модуль `ск_ПечатьЭтикетокСервер`: формирование табличного документа с этикетками
  (наименование, артикул, изображение штрихкода, цифры кода).
- Команды «Печать этикеток»: в справочнике номенклатуры (по выделенным позициям)
  и в документе прихода (количество этикеток = количество в строке).

### 4. Интерфейс и права

- Подсистема `ск_СкладскойУчет` со всеми объектами.
- Роль `ск_СкладскойУчет` с правами на объекты расширения.

### 5. Проверка

- Загрузка расширения в db001, обновление БД.
- Сценарий: приход 10 шт. → резерв 4 шт. → попытка резерва 7 шт. (ошибка) → расход 4 шт. по резерву →
  отчет показывает нулевой резерв; печать этикеток формирует корректный EAN-13.
