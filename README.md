# inventory-ext — расширение 1С «Складской учет номенклатуры»

Расширение конфигурации 1С:Предприятие 8.3 (`СкладскойУчет`, префикс `ск_`), которое добавляет:

1. **Документы по работе с номенклатурой** — «Приход товаров», «Расход товаров», «Резерв товаров»
   с контролем остатков и резервов при проведении.
2. **Отчет «Товары в резерве»** (СКД) — резерв по складам, номенклатуре и документам резерва,
   остаток на складе и свободный остаток на выбранную дату.
3. **Печать этикеток со штрихкодом EAN-13** — из справочника номенклатуры и из документа прихода
   (количество этикеток = количеству в документе). Изображение штрихкода строится встроенным языком,
   без внешних компонент и БСП.

План и проектные решения — в [docs/PLAN.md](docs/PLAN.md).

## Состав

| Тип | Объект | Назначение |
|---|---|---|
| Справочник | `ск_Номенклатура` | Артикул, единица измерения, штрихкод EAN-13 (если пуст — генерируется внутренний `200` + код + контрольная цифра) |
| Справочник | `ск_Склады` | Склады |
| Документ | `ск_ПриходТоваров` | Поступление на склад, команда «Этикетки» |
| Документ | `ск_РезервТоваров` | Резервирование свободного остатка |
| Документ | `ск_РасходТоваров` | Отгрузка; при указании резерва списывает его. Вводится на основании резерва |
| Регистр накопления | `ск_ТоварыНаСкладах` | Остатки: Номенклатура, Склад |
| Регистр накопления | `ск_ТоварыВРезерве` | Остатки: Номенклатура, Склад, ДокументРезерва |
| Отчет | `ск_ТоварыВРезерве` | Отчет по товарам в резерве |
| Общие модули | `ск_СкладскойУчетСервер`, `ск_ШтрихкодыСервер`, `ск_ПечатьЭтикетокВызовСервера` | Блокировки и контроль остатков, EAN-13, печать |
| Подсистема / роль | `ск_СкладскойУчет` | Раздел интерфейса и права |

### Правила контроля

- Остаток на складе не может стать отрицательным.
- Резерв не может превышать физический остаток: свободный остаток = остаток − резерв ≥ 0.
  Поэтому нельзя зарезервировать больше свободного и нельзя отгрузить чужой резерв.
- Нельзя уменьшить или отменить резерв ниже уже отгруженного по нему количества.
- Контроль выполняется после записи движений под исключительными управляемыми блокировками,
  в том числе при перепроведении и отмене проведения прихода.

## Структура репозитория

```
src/cfe/                  исходники расширения в формате выгрузки Конфигуратора (XML + BSL)
tools/load-extension.ps1  загрузка расширения в базу и обновление БД
tools/fill-uuids.ps1      выдача GUID новым объектам (маркер @NEWUUID@)
tools/smoke-test.js       дымовой тест через COM-соединение
tools/seed-data.js        демонстрационные данные: 2 склада, 10 товаров, приходы, резервы, расходы
docs/PLAN.md              план реализации
```

## Установка

Требуется платформа 8.3.27 (режим совместимости расширения 8.3.18). Конфигуратор с базой должен быть закрыт.

```powershell
.\tools\load-extension.ps1 -InfoBase 'D:\path\to\infobase'
```

Либо вручную: Конфигуратор → Конфигурация → Расширения конфигурации → Добавить →
«Загрузить расширение из файлов» → каталог `src/cfe`.

## Демо-данные

```powershell
C:\Windows\SysWOW64\cscript.exe //nologo //U tools\seed-data.js
```

Создает склады «Основной склад» и «Магазин на Ленина», 10 позиций номенклатуры (штрихкоды формируются
автоматически), 3 прихода, 3 резерва и 3 расхода, включая частичную отгрузку по резерву.
Повторный запуск дублей не создает.

## Проверка

```powershell
C:\Windows\SysWOW64\cscript.exe //nologo //U tools\smoke-test.js
```

Тест создает склад и товар и проходит сценарий: приход 10 → резерв 4 → резерв 7 (отказ) →
расход 7 без резерва (отказ) → расход 4 по резерву → отчет → этикетки (PDF в `%TEMP%\cfe-smoke`).

Нужен зарегистрированный COM-коннектор той же разрядности, что и `cscript`
(для x86: `regsvr32 "C:\Program Files (x86)\1cv8\<версия>\bin\comcntr.dll"` от администратора).
Тест написан на JScript, потому что PowerShell не видит динамические члены COM-объектов 1С
(метаданные, реквизиты). Файл хранится в UTF-16 LE — этого требует `cscript`.
